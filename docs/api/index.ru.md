# Начало работы

Через API можно покупать и публиковать заказы, загружать в них аккаунты и следить за слотами — без бота и веб-версии.

## Доступ {#access}

Доступ бесплатный и включается по запросу: напишите в поддержку [@freidbase](https://t.me/freidbase). Когда его включат, в рабочем боте [@kycportal_bot](https://t.me/kycportal_bot) появится кнопка «🔑 API», а в веб-версии [app.kycportal.org](https://app.kycportal.org) раздел «API» (группа «Инструменты») покажет кнопку «Создать ключ».

## Ключи {#keys}

- Ключ — строка `kp_live_` и ещё 43 символа.
- Активных ключей — до **10**.
- Права выбираются при создании и потом не меняются: нужен другой набор — создайте новый ключ ([права](#scopes)).
- Ключ можно ограничить списком до **20** адресов IPv4 или IPv6 и подсетей вида `203.0.113.0/24`. Пустой список — любой IP. Если сервер выходит в интернет и по IPv6, добавьте и его IPv6-адрес.

!!! warning
    Ключ показывается один раз — при создании. Сохраните его сразу. Любой, у кого есть ключ, управляет аккаунтом в пределах прав ключа: потеряли его или подозреваете утечку — отзовите.

### Создать ключ в боте

1. В личном чате с [@kycportal_bot](https://t.me/kycportal_bot) нажмите «🔑 API», затем «➕ Новый ключ».
2. Пришлите название ключа — до 64 символов.
3. Включите нужные права — «▫️ Загрузка аккаунтов», «▫️ Деньги» — и нажмите «Продолжить».
4. Пришлите IP-адреса или подсети через запятую или пробел — или нажмите «Любой IP».
5. Нажмите «✅ Создать». Ключ придёт отдельным сообщением и копируется нажатием. Сохраните его и нажмите «✅ Я сохранил». Через 10 минут сообщение удалится само.

### Создать ключ в веб-версии

1. Откройте раздел «API» и нажмите «Создать ключ».
2. Заполните «Название», отметьте «Права» и при необходимости «Разрешённые IP (необязательно)». Нажмите «Создать ключ».
3. Нажмите «Копировать ключ», затем «Я сохранил ключ». После закрытия окна ключ больше не показать.

### Отозвать ключ

- **В боте:** «🔑 API» → кнопка ключа «🗑 название …1234» → «🗑 Отозвать».
- **В веб-версии:** «Отозвать» у ключа, затем «Отозвать» в окне подтверждения.

Отзыв окончательный и действует со следующего запроса. Пока доступ к API выключен, ключи не показываются — отозвать ключ в это время поможет поддержка.

## Авторизация {#auth}

Адрес API — `https://app.kycportal.org/api/v1`, пути в документации указаны относительно него. Передавайте ключ в каждом запросе в заголовке `Authorization: Bearer <ключ>`.

```bash
curl https://app.kycportal.org/api/v1/ping \
  -H "Authorization: Bearer $KP_API_KEY"
```

Ответ `200`:

```json
{"client_id": 123456789, "scopes": ["read", "upload"]}
```

`client_id` — номер вашего аккаунта (Telegram ID), `scopes` — права ключа. Ключ не принят — ответ `401` или `403` ([коды](errors.md#codes)).

## Права ключа {#scopes}

| Право | При создании | Что разрешает |
|---|---|---|
| `read` | «Чтение», есть у каждого ключа | Все чтения, лента событий, адрес для пополнения |
| `upload` | «Загрузка аккаунтов» | Загрузка и замена аккаунтов и прокси, публикация, повторная загрузка, Check KYC, код BingX, скриншоты депозитов, аккаунты и скриншоты массовой реверификации |
| `money` | «Деньги» | Всё, что списывает или возвращает деньги: покупка заказов и подписки, запуск и повтор массовой реверификации, отмены |

Права независимы: можно выдать `money` без `upload` и наоборот. Право, которое нужно методу, указано на его странице.

## Общие правила {#conventions}

Типы полей в описаниях методов:

| Тип | Как выглядит в JSON |
|---|---|
| строка | `"adspower"` |
| целое | `42` |
| да/нет | `true` или `false` |
| сумма | Строка с точкой, в долларах США: `"12.50"`. В запросах тоже передавайте суммы строкой |
| время | ISO 8601 в UTC: `"2026-10-30T12:00:00Z"`, бывает с долями секунды: `"2026-10-30T12:00:00.123456Z"` |
| номер | Номер заказа, слота или исполнителя: `"8402-9173"` |
| список | `["read", "upload"]` |
| объект | `{"step": "awaiting_code", …}` |

«или `null`» после типа — поле бывает `null`.

- Запросы и ответы — JSON. Методы с файлами принимают `multipart/form-data`.
- Каждое поле ответа есть всегда; если значения нет — `null`.
- Со временем появляются новые поля и значения кодов — пропускайте незнакомые.
- Другие идентификаторы (`id` события, `batch_id`, `id` скриншота) передавайте обратно в том виде, в каком получили.
- Длительности — целые числа; единица указана в названии поля: `…_seconds`, `min_hours`, `duration_days`.
- Ставьте таймаут HTTP не меньше 120 секунд: методы, которые обращаются к бирже через ваш прокси, отвечают до полутора минут.

### Списки {#pagination}

`GET /orders`, `GET /slots`, `GET /reverify` и `GET /transactions` отдают список страницами:

| Параметр | Тип | Обязательно | Описание |
|---|---|---|---|
| `limit` | целое | нет | От 1 до 100, по умолчанию 20 |
| `offset` | целое | нет | От 0 до 10 000, по умолчанию 0 |

```json
{"items": [], "total": 57, "offset": 0, "limit": 20}
```

Новые записи идут первыми. Следующая страница — `offset + limit`, пока `offset` меньше `total`. Так же листаются участники в поле `members` у `GET /team`.

## Порядок работы {#flow}

1. Выберите товар и цену: [`GET /catalog`](orders.md#get-catalog).
2. Купите заказ: [`POST /orders`](orders.md#post-orders).
3. Загрузите аккаунты — [`POST /orders/{order_id}/upload`](upload.md#post-upload) — и опрашивайте [`GET /orders/{order_id}/upload`](upload.md#get-upload), пока проверка не закончится. Отклонённые аккаунты загрузите снова.
4. Когда во всех слотах есть аккаунт, опубликуйте заказ: [`POST /orders/{order_id}/publish`](upload.md#post-publish).
5. Опрашивайте ленту [`GET /events`](events.md#get-events) раз в 10–30 секунд.
6. На `slot_action_required` и `REUPLOAD_REQUIRED` прочитайте [слот](orders.md#get-slot) и сделайте то, что указано в `waiting_for_client`: [код BingX](slot-actions.md#post-bingx-code), [скриншоты депозитов](slot-actions.md#post-slot-risk-proofs) или [повторная загрузка](slot-actions.md#post-reupload).
