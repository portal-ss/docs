# Стрічка подій

### Отримати події {#get-events}

<div class="api-endpoint"><span class="api-method api-method--get">GET</span><code><span class="api-base">https://app.kycportal.org/api/v1</span>/events</code></div>

Повертає події щодо ваших замовлень, слотів і балансу після курсора.

Право `read`

| Параметр | Тип | Обов'язково | Опис |
|---|---|---|---|
| `cursor` | рядок | ні | Курсор із попередньої відповіді; без нього стрічка починається з цього моменту |

Відповідь `200`:

```json
{
  "events": [
    {"id": "3f9c2a7b1e0d4c58a6b2f1e9d0c7a4b3", "at": "2026-10-30T11:40:02Z", "kind": "slot_action_required",
     "order_id": "8402-9173", "slot_id": "5120-3562", "status": "BINGX_FACE_OFF",
     "balance_event": null, "cash_delta": null, "referral_delta": null,
     "action": "bingx_code", "reason": "first", "notice": null},
    {"id": "a1b2c3d4e5f60718293a4b5c6d7e8f90", "at": "2026-10-30T11:42:10Z", "kind": "balance",
     "order_id": "8402-9173", "slot_id": null, "status": null,
     "balance_event": "refund", "cash_delta": "8.00", "referral_delta": "0.00",
     "action": null, "reason": null, "notice": null}
  ],
  "cursor": "gAAAAABn…",
  "has_more": false
}
```

| Поле події | Опис |
|---|---|
| `id` | Номер події; за ним відсіюйте повтори |
| `kind` | [Вид події](#events) |
| `order_id` | У `balance` — лише якщо рух грошей стосується вашого замовлення |
| `status` | У `order_status` і `slot_status` — новий статус ([слота](codes.md#slot-statuses), [замовлення](codes.md#order-statuses)); у запиту й новини — статус на цей момент |
| `balance_event` | Лише в `balance`: [вид руху](codes.md#balance-events) |
| `cash_delta`, `referral_delta` | Лише в `balance`: зміна основного й реферального балансу; мінус — списання |
| `action` | Лише в `slot_action_required`: [що зробити](codes.md#actions) |
| `reason` | У запиту — [чому просять](codes.md#ask-reasons); у `CANCELLED` — [чому закрито](codes.md#close-reasons); у `COMPLETED` слота BingX — [підсумок другого етапу](codes.md#bingx-endings). У старих подій — `null` |
| `notice` | Лише в `slot_notice` і `order_notice`: [яка новина](codes.md#notices) |

| HTTP | `code` | Коли |
|---|---|---|
| 410 | `cursor_expired` | Курсор старший за 7 днів |
| 422 | `invalid_cursor` | Курсор видано не цим API |

## Курсор {#cursor}

- Перший запит — без курсора: порожній `events`, свіжий `cursor` і `has_more: false`. Що було раніше — у списках замовлень і слотів.
- Далі надсилайте `cursor` з останньої відповіді. Зберігайте його, щоб після перезапуску продовжити з того самого місця.
- `has_more: true` — прийшла лише частина: одразу запитайте знову. У такій порції подій може бути менше, ніж зазвичай, і навіть нуль.
- Курсор діє 7 днів і за регулярного опитування оновлюється, навіть коли подій немає.
- На `410 cursor_expired` і `422 invalid_cursor` перечитайте списки й почніть стрічку без курсора.
- Не розбирайте й не складайте курсор самі.

## Доставка

Подія приходить щонайменше один раз, але може прийти й повторно.

- Кожен запит заново повертає події за останні 60 секунд перед попереднім запитом: так не губляться події, записані із затримкою. Пропускайте події з `id`, який уже бачили, — зберігати `id` достатньо 10 хвилин.
- Зрідка, після обслуговування платформи, нещодавні події приходять ще раз під новими `id`. Тому перед дією читайте слот: якщо він уже нічого не чекає, нічого не робіть.
- В одній відповіді події впорядковано за `at`, але подія із затримкою може прийти пізніше за новішу. Поточний стан показує читання слота або замовлення.

## Види подій {#events}

| `kind` | Коли приходить |
|---|---|
| `order_status` | Змінився статус замовлення |
| `slot_status` | Змінився статус слота. `REUPLOAD_REQUIRED` — слот чекає [повторного завантаження](slot-actions.md#post-reupload); у `CANCELLED` причина — в `reason`, повернення прийде окремою подією `balance` |
| `balance` | Рух балансу: поповнення, списання, повернення, реферальний бонус, коригування |
| `slot_action_required` | Слот чекає ваших дій, навіть якщо статус не змінювався: прочитайте [слот](orders.md#get-slot) і дійте відповідно до `action` |
| `slot_notice` | Новина щодо слота без зміни статусу |
| `order_notice` | Новина щодо замовлення без зміни статусу |

- Слот BingX чекав код, а потім знадобилося повторне завантаження. Після заміни лише проксі прийде новий `slot_action_required` із тією самою причиною. Після нових cookies другий етап почнеться заново, і запит прийде з новим листом BingX.
- Кожну подію `order_frozen` згодом закриває `order_unfrozen`, якщо на момент поновлення підписки замовлення ще відкрите. `order_unfrozen` може прийти й без `order_frozen`.

## Цикл опитування

1. Під час запуску отримайте курсор — `GET /events` без параметрів, — потім прочитайте `GET /slots?attention=true` і відповідайте на те, чого чекають слоти. Перший запит із цим курсором повторить останні 60 секунд, тому між цими кроками нічого не загубиться.
2. Раз на 10–30 секунд викликайте `GET /events?cursor=…`; якщо `has_more: true` — одразу ще раз.
3. Обробіть події з новим `id` і збережіть новий курсор.
4. `410` або `422` — поверніться до кроку 1. `429` — зачекайте `Retry-After` і повторіть із тим самим курсором. Збій мережі або `5xx` — повторіть із тим самим курсором через 10–30 секунд. `401` або `403` — зупиніться: ключ відкликано, доступ вимкнено або IP-адреси немає в списку ключа.
