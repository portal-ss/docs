# Початок роботи

Через API можна купувати й публікувати замовлення, завантажувати в них акаунти та стежити за слотами — без бота й вебверсії.

## Доступ {#access}

Доступ безкоштовний і вмикається на запит: напишіть у підтримку [@freidbase](https://t.me/freidbase). Коли його ввімкнуть, у робочому боті [@kycportal_bot](https://t.me/kycportal_bot) з'явиться кнопка «🔑 API», а у вебверсії [app.kycportal.org](https://app.kycportal.org) розділ «API» (група «Інструменти») покаже кнопку «Створити ключ».

## Ключі {#keys}

- Ключ — рядок `kp_live_` і ще 43 символи.
- Активних ключів — до **10**.
- Права обираються під час створення й потім не змінюються: потрібен інший набір — створіть новий ключ ([права](#scopes)).
- Ключ можна обмежити списком до **20** адрес IPv4 або IPv6 і підмереж формату `203.0.113.0/24`. Порожній список — будь-яка IP-адреса. Якщо сервер виходить в інтернет ще й через IPv6, додайте також його IPv6-адресу.

!!! warning
    Ключ показується один раз — під час створення. Збережіть його одразу. Будь-хто, у кого є ключ, керує акаунтом у межах прав ключа: загубили його або підозрюєте витік — відкличте.

### Створити ключ у боті

1. В особистому чаті з [@kycportal_bot](https://t.me/kycportal_bot) натисніть «🔑 API», потім «➕ Новий ключ».
2. Надішліть назву ключа — до 64 символів.
3. Увімкніть потрібні права — «▫️ Завантаження акаунтів», «▫️ Гроші» — і натисніть «Продовжити».
4. Надішліть IP-адреси або підмережі через кому чи пробіл — або натисніть «Будь-який IP».
5. Натисніть «✅ Створити». Ключ прийде окремим повідомленням і копіюється натисканням. Збережіть його й натисніть «✅ Я зберіг». Через 10 хвилин повідомлення видалиться саме.

### Створити ключ у вебверсії

1. Відкрийте розділ «API» і натисніть «Створити ключ».
2. Заповніть поле «Назва», позначте «Права» і за потреби — «Дозволені IP (необов’язково)». Натисніть «Створити ключ».
3. Натисніть «Копіювати ключ», потім «Я зберіг ключ». Після закриття вікна ключ уже не побачити.

### Відкликати ключ

- **У боті:** «🔑 API» → кнопка ключа «🗑 назва …1234» → «🗑 Відкликати».
- **У вебверсії:** «Відкликати» біля ключа, потім «Відкликати» у вікні підтвердження.

Відкликання остаточне й діє з наступного запиту. Поки доступ до API вимкнено, ключі не показуються — відкликати ключ у цей час допоможе підтримка.

## Авторизація {#auth}

Адреса API — `https://app.kycportal.org/api/v1`, шляхи в документації вказано відносно неї. Передавайте ключ у кожному запиті в заголовку `Authorization: Bearer <ключ>`.

```bash
curl https://app.kycportal.org/api/v1/ping \
  -H "Authorization: Bearer $KP_API_KEY"
```

Відповідь `200`:

```json
{"client_id": 123456789, "scopes": ["read", "upload"]}
```

`client_id` — номер вашого акаунта (Telegram ID), `scopes` — права ключа. Ключ не прийнято — відповідь `401` або `403` ([коди](errors.md#codes)).

## Права ключа {#scopes}

| Право | Під час створення | Що дозволяє |
|---|---|---|
| `read` | «Читання», є в кожного ключа | Усі читання, стрічка подій, адреса для поповнення |
| `upload` | «Завантаження акаунтів» | Завантаження й заміна акаунтів і проксі, публікація, повторне завантаження, Check KYC, код BingX, скриншоти депозитів, акаунти й скриншоти масової реверифікації |
| `money` | «Гроші» | Усе, що списує або повертає гроші: купівля замовлень і підписки, запуск і повтор масової реверифікації, скасування |

Права незалежні: можна видати `money` без `upload` і навпаки. Право, потрібне методу, вказано на його сторінці.

## Загальні правила {#conventions}

Типи полів в описах методів:

| Тип | Як виглядає в JSON |
|---|---|
| рядок | `"adspower"` |
| ціле | `42` |
| так/ні | `true` або `false` |
| сума | Рядок із крапкою, у доларах США: `"12.50"`. У запитах теж передавайте суми рядком |
| час | ISO 8601 в UTC: `"2026-10-30T12:00:00Z"`, буває з частками секунди: `"2026-10-30T12:00:00.123456Z"` |
| номер | Номер замовлення, слота або виконавця: `"8402-9173"` |
| список | `["read", "upload"]` |
| об'єкт | `{"step": "awaiting_code", …}` |

«або `null`» після типу — поле буває `null`.

- Запити й відповіді — JSON. Методи з файлами приймають `multipart/form-data`.
- Кожне поле відповіді присутнє завжди; якщо значення немає — `null`.
- З часом з'являються нові поля й значення кодів — пропускайте незнайомі.
- Інші ідентифікатори (`id` події, `batch_id`, `id` скриншота) передавайте назад у тому вигляді, у якому отримали.
- Тривалості — цілі числа; одиницю вказано в назві поля: `…_seconds`, `min_hours`, `duration_days`.
- Ставте таймаут HTTP щонайменше 120 секунд: методи, які звертаються до біржі через ваш проксі, можуть відповідати до півтори хвилини.

### Списки {#pagination}

`GET /orders`, `GET /slots`, `GET /reverify` і `GET /transactions` повертають список посторінково:

| Параметр | Тип | Обов'язково | Опис |
|---|---|---|---|
| `limit` | ціле | ні | Від 1 до 100, за замовчуванням 20 |
| `offset` | ціле | ні | Від 0 до 10 000, за замовчуванням 0 |

```json
{"items": [], "total": 57, "offset": 0, "limit": 20}
```

Нові записи йдуть першими. Наступна сторінка — `offset + limit`, поки `offset` менший за `total`. Так само гортаються учасники в полі `members` у `GET /team`.

## Порядок роботи {#flow}

1. Оберіть товар і ціну: [`GET /catalog`](orders.md#get-catalog).
2. Купіть замовлення: [`POST /orders`](orders.md#post-orders).
3. Завантажте акаунти — [`POST /orders/{order_id}/upload`](upload.md#post-upload) — і опитуйте [`GET /orders/{order_id}/upload`](upload.md#get-upload), поки перевірка не закінчиться. Відхилені акаунти завантажте знову.
4. Коли в усіх слотах є акаунт, опублікуйте замовлення: [`POST /orders/{order_id}/publish`](upload.md#post-publish).
5. Опитуйте стрічку [`GET /events`](events.md#get-events) раз на 10–30 секунд.
6. На `slot_action_required` і `REUPLOAD_REQUIRED` прочитайте [слот](orders.md#get-slot) і зробіть те, що вказано в `waiting_for_client`: [код BingX](slot-actions.md#post-bingx-code), [скриншоти депозитів](slot-actions.md#post-slot-risk-proofs) або [повторне завантаження](slot-actions.md#post-reupload).
