# Лента событий

### Получить события {#get-events}

<div class="api-endpoint"><span class="api-method api-method--get">GET</span><code><span class="api-base">https://app.kycportal.org/api/v1</span>/events</code></div>

Возвращает события по вашим заказам, слотам и балансу после курсора.

Право `read`

| Параметр | Тип | Обязательно | Описание |
|---|---|---|---|
| `cursor` | строка | нет | Курсор из прошлого ответа; без него лента начинается сейчас |

Ответ `200`:

```json
{
  "events": [
    {"id": "3f9c2a7b1e0d4c58a6b2f1e9d0c7a4b3", "at": "2026-10-30T11:40:02Z", "kind": "slot_action_required",
     "order_id": "8402-9173", "slot_id": "5120-3562", "status": "BINGX_FACE_OFF",
     "balance_event": null, "cash_delta": null, "referral_delta": null,
     "action": "bingx_code", "reason": "first", "notice": null},
    {"id": "a1b2c3d4e5f60718293a4b5c6d7e8f90", "at": "2026-10-30T11:42:10Z", "kind": "balance",
     "order_id": "8402-9173", "slot_id": null, "status": null,
     "balance_event": "refund", "cash_delta": "8.00", "referral_delta": "0.00",
     "action": null, "reason": null, "notice": null}
  ],
  "cursor": "gAAAAABn…",
  "has_more": false
}
```

| Поле события | Описание |
|---|---|
| `id` | Номер события; по нему отсеивайте повторы |
| `kind` | [Вид события](#events) |
| `order_id` | У `balance` — только если движение денег касается вашего заказа |
| `status` | У `order_status` и `slot_status` — новый статус ([слота](codes.md#slot-statuses), [заказа](codes.md#order-statuses)); у запроса и новости — статус в этот момент |
| `balance_event` | Только у `balance`: [вид движения](codes.md#balance-events) |
| `cash_delta`, `referral_delta` | Только у `balance`: изменение основного и реферального баланса; минус — списание |
| `action` | Только у `slot_action_required`: [что сделать](codes.md#actions) |
| `reason` | У запроса — [почему просят](codes.md#ask-reasons); у `CANCELLED` — [почему закрыт](codes.md#close-reasons); у `COMPLETED` слота BingX — [итог второго этапа](codes.md#bingx-endings). У старых событий — `null` |
| `notice` | Только у `slot_notice` и `order_notice`: [что за новость](codes.md#notices) |

| HTTP | `code` | Когда |
|---|---|---|
| 410 | `cursor_expired` | Курсор старше 7 дней |
| 422 | `invalid_cursor` | Курсор выдан не этим API |

## Курсор {#cursor}

- Первый запрос — без курсора: пустой `events`, свежий `cursor` и `has_more: false`. Что было раньше — в списках заказов и слотов.
- Дальше отправляйте `cursor` из последнего ответа. Сохраняйте его, чтобы после перезапуска продолжить с того же места.
- `has_more: true` — пришла только часть: сразу запросите снова. В такой порции событий может быть меньше обычного и даже ноль.
- Курсор действует 7 дней и при регулярном опросе обновляется, даже когда событий нет.
- На `410 cursor_expired` и `422 invalid_cursor` перечитайте списки и начните ленту без курсора.
- Не разбирайте и не собирайте курсор сами.

## Доставка

Событие приходит минимум один раз, но может прийти и повторно.

- Каждый запрос заново отдаёт события последних 60 секунд перед прошлым запросом: так не теряются события, записанные с задержкой. Пропускайте события с уже виденным `id` — хранить `id` достаточно 10 минут.
- Изредка, после обслуживания платформы, недавние события приходят ещё раз под новыми `id`. Поэтому перед действием читайте слот: если он уже ничего не ждёт, ничего не делайте.
- В одном ответе события идут по `at`, но событие с задержкой может прийти позже более нового. Текущее состояние — в чтении слота или заказа.

## Виды событий {#events}

| `kind` | Когда приходит |
|---|---|
| `order_status` | Изменился статус заказа |
| `slot_status` | Изменился статус слота. `REUPLOAD_REQUIRED` — слот ждёт [повторной загрузки](slot-actions.md#post-reupload); у `CANCELLED` в `reason` причина, возврат придёт отдельным событием `balance` |
| `balance` | Движение баланса: пополнение, списание, возврат, реферальный бонус, корректировка |
| `slot_action_required` | Слот ждёт ваших действий, даже если статус не менялся: прочитайте [слот](orders.md#get-slot) и ответьте по `action` |
| `slot_notice` | Новость по слоту без смены статуса |
| `order_notice` | Новость по заказу без смены статуса |

- Слот BingX ждал код и ушёл на повторную загрузку. После замены только прокси придёт новый `slot_action_required` с прежней причиной. После новых cookies второй этап начнётся заново, и запрос придёт с новым письмом BingX.
- Каждое `order_frozen` позже закрывается `order_unfrozen`, если заказ к продлению подписки ещё открыт. `order_unfrozen` может прийти и без `order_frozen`.

## Цикл опроса

1. При запуске получите курсор — `GET /events` без параметров, — затем прочитайте `GET /slots?attention=true` и ответьте на то, что ждут слоты. Первый запрос с этим курсором повторит последние 60 секунд, поэтому между ними ничего не потеряется.
2. Раз в 10–30 секунд вызывайте `GET /events?cursor=…`; при `has_more: true` — сразу ещё раз.
3. Обработайте события с новым `id` и сохраните новый курсор.
4. `410` или `422` — вернитесь к шагу 1. `429` — подождите `Retry-After` и повторите с тем же курсором. Сбой сети или `5xx` — повторите с тем же курсором через 10–30 секунд. `401` или `403` — остановитесь: ключ отозван, доступ выключен или IP не в списке ключа.
