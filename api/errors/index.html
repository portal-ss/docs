    Ошибки и лимиты¶

    Формат ошибки¶

    Ошибка приходит со статусом 4xx или 5xx и телом:

    {"detail": {"code": "price_changed", "price": "13.00", "total": "65.00",
  "message": "The live price is above the one you sent; nothing was charged. See 'price' and 'total'."}}
    • code — постоянный код. Решайте, что делать, по HTTP-статусу и code.
    • message — фраза на английском для логов. Она может меняться — не разбирайте её.
    • Остальные поля — уточнения к коду; какие бывают, сказано в таблицах ниже.
    • Незнакомый код: 4xx — запрос нужно менять, 5xx — повторите позже.
    • Испорченная multipart-форма (поле больше 1 МБ, слишком много полей) получает 400, где detail — строка без code.

    Общие ошибки¶

    Их может вернуть любой метод. Ошибки конкретного метода — на странице метода.

    HTTP code Что значит и что делать
    401 invalid_api_key Ключа нет, заголовок не Authorization: Bearer <ключ> или такого ключа нет
    401 api_key_revoked Ключ отозван — создайте новый
    403 api_not_enabled Доступ к API выключен. Ключи сохранены и заработают, когда доступ вернут. Напишите в поддержку
    403 banned Аккаунт заблокирован — напишите в поддержку
    403 ip_not_allowed IP запроса нет в списке ключа
    403 scope_required У ключа нет права scope — создайте ключ с этим правом
    404 order_not_found Нет такого заказа у вас. Чужой и несуществующий заказ отвечают одинаково
    404 slot_not_found Нет такого слота в этом заказе у вас — на любом пути со слотом, даже если неверен номер заказа
    404 not_found Нет такого метода
    405 method_not_allowed Метод не принимает этот HTTP-глагол
    411 length_required Форма с файлом отправлена частями — нужен Content-Length
    413 payload_too_large Тело больше допустимого
    415 unsupported_media_type Метод с файлами ждёт multipart/form-data
    422 validation_error Запрос не соответствует описанию; field — где первая ошибка: body.quantity, query.limit, header.Idempotency-Key, path.order_id или path.slot_id (номер не в виде 8402-9173). Так же отвечает запрос без обязательного Idempotency-Key
    422 invalid_idempotency_key Idempotency-Key не в формате
    422 idempotency_key_reused Этот Idempotency-Key уже использован для другого запроса — новое действие, новый ключ
    409 idempotency_in_progress Запрос с этим Idempotency-Key ещё выполняется — повторите через несколько секунд с тем же ключом
    429 rate_limited Превышен лимит — подождите Retry-After секунд
    500 internal_error Сбой платформы — повторите позже; повторяется — напишите в поддержку
    503 try_again Ничего не сделано — повторите с тем же Idempotency-Key
    503 queue_unavailable Платформа занята, ничего не сделано — повторите через несколько секунд (через retry_after_seconds, если оно есть)

    Лимиты запросов¶

    Счётчик Лимит Методы
    Чтение 300 за 60 с Каждый GET
    Запись 60 за 60 с Каждый POST, PUT, DELETE
    Списки 60 за 60 с GET /orders, /slots, /reverify, /transactions, /team
    Лента 30 за 60 с GET /events
    Загрузка 20 за 60 с POST /orders/{order_id}/upload, …/slots/{slot_id}/proxy, …/reupload, …/replace-proxy, …/start-proxy-replace, POST /reverify/batches
    Деньги 15 за 60 с POST /orders, POST /subscription, …/cancel, …/cancel-frozen, …/cancel-reverify, POST /reverify/batches/{batch_id}/execute, …/retry
    Check KYC 60 за 3600 с POST …/check-kyc
    Новый код BingX 60 за 60 с POST …/bingx-code/refresh
    • Каждый счётчик считается и на ключ, и на аккаунт: запрос проходит, только если не превышен ни тот, ни другой. Десять ключей не дают десяти лимитов.
    • Запрос тратит общий счётчик (чтение или запись) и свой, если он есть: GET /orders — одно чтение и один список.
    • Окно фиксированное: отсчёт идёт от первого запроса в окне. Отклонённые запросы тоже считаются.
    • Сверх лимита — 429 rate_limited с заголовком Retry-After: секунды до конца окна.
    • После 30 ответов invalid_api_key за 60 секунд с одного IP запросы с неизвестным ключом с этого IP получают 429 rate_limited до конца окна. Верный ключ с этого IP продолжает работать.

    Одновременные операции¶

    Отказ снимается, когда закончится то, что уже идёт. Retry-After есть только у cooldown.

    Что Сколько Ответ
    Загрузки в проверке — по всем заказам, вместе с ботом и веб-версией 2 на аккаунт 429 upload_concurrency_limit, 409 too_many_uploads
    Проверка загрузки одного заказа 1 409 upload_in_progress
    Обращения к бирже по вашим слотам: Check KYC, смена прокси, повторная загрузка 3 429 client_exchange_busy
    Проверка одного слота 1; следующая — через 30 с, после неудачной — через 15 с 409 check_in_flight, 429 cooldown
    Покупка 1 409 purchase_in_progress
    Проверка пакета массовой реверификации 1 409 reverify_validate_in_progress
    Запуск массовой реверификации 1 409 reverify_in_progress

    Размер запроса¶

    Запрос Предел
    JSON-тело любого метода, кроме указанных ниже 64 КБ
    PUT /reverify/batches/{batch_id}/proofs 1 000 000 байт
    POST /orders/{order_id}/upload, POST /reverify/batches 34 МБ; файл ADS Power — до 20 МБ; файл cookies — до 8 МБ, все вместе — до 32 МБ; поле proxies — до 1 МБ; до 200 аккаунтов
    POST …/slots/{slot_id}/reupload 22 МБ
    POST /risk-proofs/files 18 МБ

    Тело больше 64 КБ принимают только методы с файлами и только в виде multipart/form-data.

    Idempotency-Key¶

    Заголовок обязателен на девяти методах: POST /orders, POST /subscription, POST /orders/{order_id}/upload, POST /reverify/batches, POST /reverify/batches/{batch_id}/execute, …/retry, POST /orders/{order_id}/cancel, …/cancel-frozen, POST …/slots/{slot_id}/cancel-reverify.

    • Формат: 8–64 символа — латинские буквы, цифры, -, _. Подходит UUID.
    • Новое действие — новый ключ. Тот же ключ — только для повтора того же запроса: метод, путь, параметры и тело байт в байт. Повторяя, отправляйте сохранённое тело, а не собирайте его заново.
    • Ключи общие для аккаунта: один и тот же Idempotency-Key с двух API-ключей — один запрос.
    • Успешный ответ хранится 24 часа. Повтор получит его же с заголовком Idempotent-Replayed: true; второй раз ничего не выполнится.
    • Ошибка не запоминается: после ответа 4xx или 5xx повтор с тем же ключом выполнится заново.
    • Покупка заказа и подписки запоминается дольше: повтор с тем же ключом и через сутки не купит второй раз. Поэтому не используйте ключ одной покупки для другой.

    У POST /risk-proofs/files свой необязательный заголовок X-Upload-Key (UUID): повтор с ним в течение 24 часов вернёт тот же скриншот.
